# 数据能力、分页与缺失值

## 时间范围

- `date` 使用 Garmin 账号本地日历日期，格式 `YYYY-MM-DD`。不要用请求发出时的 UTC 日期替代用户当地日期。
- `startDate` 和 `endDate` 均包含在范围内；跨度最大 31 天。连续批次的下一段从上一段结束日期的次日开始，避免重复计算。
- 代码没有滚动历史窗口，也没有“部署后才开始有数据”的限制。可读的最早日期由 Garmin 上游决定，尚未证明所有历史均开放。
- `retrievedAt` 是本次读取时间，**不是**测量时间或最后同步时间。今天的记录可能仍不完整。

## 分页

- `garmin_activities`：默认 `offset=0, limit=20`，`limit` 最大 50。响应 `nextOffset` 非空时继续请求同一日期范围；如果刚好满页，可能需要再查一个空页才能结束。空页本身不证明 Garmin 所有历史已完整返回。
- `garmin_series`：默认 `offset=0, limit=120`，`limit` 最大 240。`totalPoints` 是当天上游返回的点数；沿 `nextOffset` 读取到 null。
- 两种工具的 `offset` 最大 100,000。此上限不是承诺上游支持如此多的数据。
- 时间序列分页发生在 Worker 投影阶段，每页仍读取上游当天响应；不是成本更低的上游游标。优先日汇总做长期分析，需要精细走势时再取序列。
- 超出 31 天应拆成多个调用。项目不实现服务器端批量导出；AI 的工具次数、上下文大小和佳明限流都可能让长时间分析无法一次完成。报告已查询范围和未完成部分。

## 数据内容

| 类别 | 已公开的内容 | 当前边界 |
|---|---|---|
| 日汇总 | 白名单中的活动、能量、心率、压力、Body Battery、血氧、呼吸、饮水字段 | 上游未提供的字段不补造 |
| 睡眠 | 时长、各阶段时长、睡眠评分等摘要 | 不提供睡眠阶段时间轴 |
| HRV | 夜间/周均值、基线、状态等摘要 | 不是逐次心搏 RR 数据 |
| 运动 | ID、运动类型、起始日期、白名单数值指标 | 不含名称/笔记/GPS/设备信息；不是完整 FIT 或分圈导出 |
| 时间序列 | 心率、Body Battery、血氧小时均值的数值行和原始列描述 | 采样频率以实际返回为准；每行最多 12 个数值单元 |
| 健身年龄 | fitnessAge、achievableFitnessAge、previousFitnessAge（如有） | 佳明估计，不是医学年龄 |

## 缺失与错误

`available=false`、空数组、null 或缺字段都是“不知道/没有返回”，不能当成零或没运动。设备不支持某个测量、同步滞后或接口范围限制都可能造成缺失。负数等原生哨兵值需结合描述解释，不能当成真实生理值。

- `DATE_RANGE`：拆分为最多 31 天的合法范围。
- `GARMIN_AUTH`：检查服务器端 Key、账号区域或有效期。
- `GARMIN_RATE_LIMIT` / HTTP 429：稍后重试，不要无限循环。
- `GARMIN_TLS` / HTTP 526：Worker 到佳明的上游 TLS 失败，不等于 Key 错误或没有数据；不要关闭证书校验。
- `NETWORK`：佳明请求不可达或超出 24 秒期限。
- `RESPONSE_TOO_LARGE`：上游响应超过 2 MB 限制；缩小日期/条数。时间序列按天读取，客户端缩小页大小未必解决上游响应过大的问题。

MCP 的 HTTP 200 也可能包含 `isError=true` 的工具结果。`/healthz` 和 `garmin_status` 只证明服务可响应或配置存在，不验证佳明认证。
